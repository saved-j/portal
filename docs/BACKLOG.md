# Portal — план работ (backlog)

Обновлено: 2026-11-16. Порядок — как решено с Марком; не «по важности вообще».

## Ждёт реализации

### 1. Подписка с одним ядром
Если в подписке есть mihomo-формат и/или xray-формат — определить на этапе загрузки и
**жёстко** привязать подписку к поддерживаемому режиму. Большинство подписок умеют только
одно ядро, сейчас неподдерживаемый режим просто падает при запуске.
Где: `lib/core/subscription_formats.dart`, `lib/models/profile.dart`, `lib/providers/actions/setup.dart`.

### 2. Два индикатора ядер в списке подписок
Зелёный/серый кружок на каждое ядро (mihomo, xray) в карточке подписки.
- зелёный — формат есть и скачался;
- серый — формата нет.
Нажатие на серый: повторная попытка скачать подписку, затем сообщение
«ваша подписка не поддерживает этот функционал. Хотите сгенерировать конфиг локально?»
с кнопками Да/Нет, где **«Да» сейчас серая** (локальной генерации нет).

### 3. Аудит — закрыто, кроме двух проверок
Решено и проверено на телефоне: B1, M1, M2, M3 (потолок 15 с в нативном замере),
M4 (релиз без keystore падает, versionName из pubspec), JNI (`GetStringUTFChars`),
тесты (`SweepLedger` 8 шт., `redactUrl` 4 шт.), редакция URL в логах.

Открыто:
- **Проверить живьём перезагрузку child при обновлении подписки.** Механизм
  `reapplyPortalDocument()` есть, портал через окно обновления остаётся Active,
  но саму строку `portal child reloaded` в логе я не поймала — нужно принудительное
  обновление подписки при открытом простом портале.
- **Отмена engine-замера** по кнопке: сейчас прогон движка отменяется только сменой
  режима/профиля, отдельной отмены нет.
- **trailing whitespace** в архивных патчах (косметика, APK не трогает).
